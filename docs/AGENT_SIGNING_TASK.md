# Даалгавар: ZkFingerprint агентад төхөөрөмжийн гарын үсэг нэмэх (v1.2.0.0)

Чи ZkFingerprint Windows агентын эх код дээр ажиллана. Агент нь **C#** дээр бичигдсэн, debug цонхтой Windows десктоп апп бөгөөд ZK9500 уншигчтай ажиллаж, WebSocket 8089 порт дээр сонсдог. Энэ агентыг өмнө нь Claude бичсэн. Протокол нь `CLIENT_GUIDE.md`-д тайлбарлагдсан.

Эхлээд төслийн target framework-ийг (.NET Framework 4.x эсвэл .NET 6+) тогтоо. Доорх API-уудыг тухайн хувилбарт тааруулж сонгоно.

Эхлээд одоогийн кодыг бүтнээр нь уншиж танилц. Мессеж хаана үүсдэг, команд хаана задлагддаг, зураг хаана base64 болдог, тохиргоо хаана хадгалагддагийг ол. Дараа нь доорх өөрчлөлтүүдийг кодын одоогийн хэв маягаар хий. Хамааралгүй кодыг бүү өөрчил. Тодорхойгүй зүйл гарвал таамаглалгүйгээр асуу.

## 1. Яагаад

Вэб клиент нь хурууны хээний зургийг backend руу илгээж, ХУР-аар баталгаажуулж нэвтэрдэг. Одоо backend зураг **аль уншигчаас ирснийг** баталж чадахгүй байна. Serial нууц биш, хэн ч хуурамчаар илгээж болно. Иймд агент суулгалт бүр өөрийн private key-тэй болж, зурагт гарын үсэг зурна.

Backend ба вэб клиент (энэ даалгаварт хамаарахгүй) дараах байдлаар ажиллана:
- Серверээс нэг удаагийн `nonce` авна.
- Агентаас тухайн nonce-оор гарын үсэг авна.
- Backend гарын үсгийг бүртгэлтэй public key-ээр шалгана.

Public key-г backend "эхний идэвхжүүлэлтээр" бэхэлнэ (`CMD_PROVE`). Иймд чиний ажил зөвхөн агентын тал.

## 2. Хийх өөрчлөлтүүд

### 2.1 Төхөөрөмжийн түлхүүр
- ECDSA **P-256** түлхүүрийг **Windows CNG-д persisted key** хэлбэрээр хадгална.
  - Нэр: `ZkFingerprint.DeviceKey.v1`
  - `ExportPolicy = None`: private key экспортлогдохгүй.
  - Файлд бичихгүй, log-д гаргахгүй.
- Машины түвшний key (`CngKeyCreationOptions.MachineKey`) байхыг илүүд үзнэ. Нэвтэрсэн Windows хэрэглэгчээс хамаарахгүй байх ёстой.
  - Десктоп апп ихэвчлэн admin эрхгүй ажилладаг бөгөөд машины key үүсгэхэд admin эрх шаардлагатай. Иймд key-г **суулгагч (elevated)** үүсгэнэ. Эсвэл апп-ыг `--init-key` аргументтайгаар нэг удаа "Run as administrator"-оор ажиллуулж үүсгэнэ.
  - Энгийн горимд апп key-г **зөвхөн нээнэ**.
  - Машины key боломжгүй бол яагаад гэдгийг тайлбарлаад хамгийн ойр хувилбарыг (жишээ нь хэрэглэгчийн түвшний key) санал болго.
- Key байвал дахин ашиглана. Агентыг restart, шинэчлэх эсвэл дахин суулгахад **ижил key** үлдэнэ.
  - Key огт байхгүй үед л шинээр үүсгэнэ.
  - Нээж чадаагүй үед шинээр **бүү** үүсгэ (бэхэлгээ эвдэрнэ). `KEY_UNAVAILABLE` буцаа.
- Эхлэхдээ log-д public key-ийн хурууны хээг бичнэ: `sha256(publicKeyBytes)`-ийн эхний 16 hex тэмдэгт. Debug цонхонд мөн энэ хурууны хээ болон key-ийн төлөвийг (машины/хэрэглэгчийн key, эсвэл алдаа) харуулна.

### 2.2 `DEVICE_INFO`-д `publicKey` нэмэх
Одоо байгаа талбаруудыг хэвээр үлдээж, payload-д `publicKey` нэмнэ:

```json
{"serial":"1985263400731","model":"ZK9500","vendor":"ZKTeco Inc.","width":300,"height":375,"publicKey":"BAx...=="}
```

- Формат: `base64( 0x04 || X(32 байт) || Y(32 байт) )`, нийт 65 байт (uncompressed point).
- .NET-д `ExportParameters(false).Q.X` ба `.Q.Y` ашиглана. Экспортлогдохгүй key ч public хэсгээ өгдөг.
- .NET Framework 4.7-оос хуучин бол `ExportParameters` байхгүй. Тэр үед `CngKey.Export(CngKeyBlobFormat.EccPublicBlob)`-ийг ашиглаад 8 байт толгойг (magic + cbKey) алгасаж, X, Y (тус бүр 32 байт)-г авна.
- Key ашиглах боломжгүй бол `"publicKey": ""`.

### 2.3 Шинэ команд `CMD_SIGN <nonce>`
Сүүлд уншсан зурагт гарын үсэг зурна.

- **Гарын үсэг зурж болох зураг** — дараах бүгд биелсэн байх ёстой:
  - Энгийн уншилтын `FINGER_IMAGE` байх. Бүртгэлийн (enroll) явцын зургийг хадгалахгүй, гарын үсэг зурахгүй.
  - Monotonic цагаар (`Stopwatch`, системийн цаг биш) авснаас хойш **≤ 60 секунд** өнгөрсөн байх.
  - Өмнө нь гарын үсэг зурагдаагүй байх. Нэг зурагт нэг л удаа зурна.
- Агент сүүлийн зургийн **яг `FINGER_IMAGE` payload-д base64 болгосон PNG байтууд**, тэр зургийг авсан уншигчийн serial, авсан цагийг санах ойд хадгална.
- Сүүлийн зургийг цэвэрлэх үеүд:
  - шинэ `FINGER_IMAGE` ирэхэд солигдоно;
  - `USB_STATUS = DISCONNECTED` үед;
  - `CMD_ENROLL_START` үед;
  - амжилттай `CMD_SIGN`-ы дараа.
- Амжилттай бол **зөвхөн команд илгээсэн клиентэд** (broadcast биш) дараах event-ийг илгээнэ:

```json
{"eventType":"FINGER_SIGNATURE","payload":{"nonce":"<nonce>","serial":"<зургийн serial>","imageSha256":"<hex>","signature":"<base64>"},"version":"1.2.0.0","serial":"<serial>"}
```

### 2.4 Шинэ команд `CMD_PROVE <nonce>`
Зураггүйгээр түлхүүр эзэмшиж буйгаа батална. Backend-ийн анхны идэвхжүүлэлтэд ашиглана.
- Уншигч холбогдсон байх шаардлагатай, эс бөгөөс `NO_DEVICE`.
- Зөвхөн илгээсэн клиентэд хариулна:

```json
{"eventType":"DEVICE_PROOF","payload":{"nonce":"<nonce>","serial":"<serial>","publicKey":"<base64>","signature":"<base64>"},"version":"1.2.0.0","serial":"<serial>"}
```

### 2.5 Командын задлал
- Одоо командууд том жижиг үсэг ялгадаггүй. **Зөвхөн командын нэрийг** ялгахгүй байлга.
- Аргументийг (nonce) **байт бүрээр нь яг хэвээр** хадгал. Бүхэл мөрийг `ToUpper()` хийвэл гарын үсэг таарахгүй болно.
- Нэр ба аргументийг нэг зайгаар тусгаарлана. Мөрийн төгсгөлийн хоосон зай, `\r\n`-ийг хасна.
- Nonce `^[A-Za-z0-9_-]{22,128}$`-д таарахгүй бол `INVALID_NONCE`. Backend 32 байт санамсаргүй тоог base64url-ээр илгээнэ (43 тэмдэгт).

### 2.6 Сүлжээний хамгаалалт
- **`ListenAddress`** тохиргоо. Анхдагч утга нь `127.0.0.1`.
  - Одоо `0.0.0.0` дээр сонсож байгаа тул LAN-ийн хэн ч холбогдоод бүх хүний хурууны хээний зургийг хүлээн авч чадна.
  - Хөгжүүлэлтэд LAN-аар туршихын тулд `0.0.0.0` гэж тусгайлан тохируулах боломжтой байлга.
- **`AllowedOrigins`** тохиргоо (таслалаар тусгаарласан жагсаалт).
  - Жагсаалт хоосон биш бол WebSocket handshake-ийн `Origin` header нь жагсаалтад байхгүй үед HTTP 403-оор татгалзана. Ингэснээр киоскийн хөтөч дээр нээгдсэн өөр вэб хуудас `ws://127.0.0.1:8089` руу холбогдож зураг авахаас сэргийлнэ.
  - `Origin`-гүй холболт (хөтөч биш локал хэрэгсэл) зөвшөөрөгдөнө.
  - Хоосон бол бүгдийг зөвшөөрч, эхлэхдээ log-д анхааруулга бичнэ.
- Тохиргоог агентын одоо байгаа тохиргооны механизмаар хадгална. Тийм механизм байхгүй бол exe-ийн хажууд `ZkFingerprint.config.json` үүсгэ.

### 2.7 Хувилбар
`version`-ийг `1.2.0.0` болгоно.

Вэб клиент агентын мессежийн `version`-ийг серверт байршуулсан хамгийн сүүлийн хувилбартай харьцуулж, "шинэчилнэ үү" гэж мэдэгддэг. Иймд дараах гурав **үргэлж ижил** байх ёстой:
- WebSocket мессежийн `version`;
- exe-ийн `FileVersion` / `ProductVersion`;
- суулгагчийн (`ZkFingerprintSetup.exe`) `ProductVersion`.

Одоогийн байдлаар суулгагч 1.0.0.1, агент 1.1.0.0 гэж зөрүүтэй байна. Хувилбарыг нэг газар (жишээ нь `AssemblyInfo` эсвэл `Directory.Build.props`) тодорхойлж, бусад нь түүнээс авдаг болго.

## 3. Криптографийн нарийн тодорхойлолт (яг ийм байх ёстой)

| Зүйл | Утга |
|---|---|
| Алгоритм | ECDSA, curve P-256, hash SHA-256 |
| Гарын үсэг | IEEE P1363 (`r‖s`, яг 64 байт), base64. .NET-ийн `ECDsa.SignData(data, HashAlgorithmName.SHA256)`-ийн анхдагч формат. DER **биш** |
| Public key | `base64(0x04‖X‖Y)`, 65 байт |
| `imageSha256` | `FINGER_IMAGE` payload-ийн base64-ийг decode хийсэн PNG байтуудын SHA-256, **жижиг үсэгтэй hex** |
| Encoding | Доорх мессежийн мөрийг UTF-8 байт болгоод гарын үсэг зурна. Мөрүүдийг `\n`-ээр тусгаарлана, төгсгөлд `\n` байхгүй |

`CMD_SIGN`-ийн мессеж:
```
ZKFP-SIGN-v1\n{serial}\n{nonce}\n{imageSha256}
```

`CMD_PROVE`-ийн мессеж:
```
ZKFP-PROVE-v1\n{serial}\n{nonce}
```

Эхний мөр (`ZKFP-SIGN-v1`, `ZKFP-PROVE-v1`) нь хоёр мессежийг ялгана. Ингэснээр PROVE-ийн гарын үсгийг нэвтрэхэд ашиглах боломжгүй.

Backend яг ийм кодоор шалгана. Боломжтой бол чи ч Node-оор хөндлөн шалга:

```js
const crypto = require('crypto');
function verify(publicKeyB64, message, signatureB64) {
  const pub = Buffer.from(publicKeyB64, 'base64'); // 65 байт: 0x04||X||Y
  const key = crypto.createPublicKey({
    key: { kty: 'EC', crv: 'P-256', x: pub.subarray(1, 33).toString('base64url'), y: pub.subarray(33, 65).toString('base64url') },
    format: 'jwk',
  });
  return crypto.verify('sha256', Buffer.from(message, 'utf8'), { key, dsaEncoding: 'ieee-p1363' }, Buffer.from(signatureB64, 'base64'));
}
```

## 4. Шинэ алдааны кодууд

Одоогийн `ERROR` хэлбэрээр, зөвхөн илгээсэн клиентэд: `{"code":"...","command":"CMD_SIGN"}`

| code | Хэзээ |
|---|---|
| `NO_FRESH_IMAGE` | Гарын үсэг зурах зураг байхгүй, 60 секундээс хуучирсан, эсвэл аль хэдийн зурагдсан |
| `INVALID_NONCE` | Nonce байхгүй эсвэл форматад таарахгүй |
| `NO_DEVICE` | `CMD_PROVE` үед уншигч холбогдоогүй |
| `KEY_UNAVAILABLE` | CNG key-г нээж, ашиглаж чадсангүй |

## 5. Бүү хий
- Мессежийн 4 талбарт бүтэц, одоо байгаа event, командуудыг өөрчлөхгүй. Хуучин клиентүүд ажилласаар байх ёстой; `DEVICE_INFO`-д талбар нэмэх нь зөвшөөрөгдөнө.
- Private key-г файл, registry, log, санах ойн dump-д гаргахгүй. Экспортлох боломжтой болгохгүй.
- Хурууны хээний зураг болон template-ийг log эсвэл диск рүү бичихгүй.
- 60 секундийн хугацааг системийн цагаар бүү хэмж (цаг солиход эвдэрнэ).
- `FINGER_SIGNATURE`, `DEVICE_PROOF`-ийг бүх клиентэд broadcast хийхгүй.

## 6. Хүлээн авах шалгуур

Боломжтойг нь unit test болго, үлдсэнийг гараар шалгаад үр дүнг тайлагна:

1. `CLIENT_GUIDE.md`-ийн 9-р хэсгийн консолын код хэвээр ажиллана. `DEVICE_INFO`-д `publicKey` нэмэгдсэн байна.
2. `publicKey` нь агентыг restart хийх болон дахин суулгахад өөрчлөгдөхгүй.
3. Зураг байхгүй үед `CMD_SIGN <nonce>` → `NO_FRESH_IMAGE`.
4. Хуруу тавиад `CMD_SIGN <nonce>` → `FINGER_SIGNATURE`:
   - `imageSha256` нь `sha256(base64decode(FINGER_IMAGE.payload))`-тэй тэнцүү;
   - 3-р хэсгийн `verify` → `true`.
5. Ижил зурагт хоёр дахь удаа `CMD_SIGN` → `NO_FRESH_IMAGE`.
6. Зураг авснаас 61 секундийн дараа `CMD_SIGN` → `NO_FRESH_IMAGE`.
7. `cmd_sign AbC-dEf_0123456789xyzXYZ` (жижиг үсэгтэй команд, холимог үсэгтэй nonce) → гарын үсэг nonce-ийн **яг** тэр утгаар зурагдсан.
8. `CMD_SIGN abc` (богино) эсвэл `CMD_SIGN` (аргументгүй) → `INVALID_NONCE`.
9. Бүртгэлийн явцын зурагт `CMD_SIGN` → `NO_FRESH_IMAGE`.
10. Зураг авсны дараа USB салгавал `CMD_SIGN` → `NO_FRESH_IMAGE`.
11. Хоёр клиент холбогдсон үед зөвхөн команд илгээсэн нь `FINGER_SIGNATURE` эсвэл `DEVICE_PROOF` хүлээн авна.
12. Анхдагч тохиргоотой үед LAN-аас холбогдож чадахгүй. `ListenAddress=0.0.0.0` үед холбогдоно.
13. `AllowedOrigins`-д байхгүй `Origin`-тэй handshake → 403. Жагсаалтад байгаа нь ажиллана.
14. Private key-г экспортлох оролдлого алдаа өгнө.
15. Self-test нь бодит device key-ээр дараах JSON-ийг үүсгэж, өөрөө `verify` хийгээд `"valid": true` гаргана. Апп консолгүй тул хоёр аргаар ажиллуулна:
    - debug цонхонд "Self-test" товч: үр дүнг харуулж, clipboard руу хуулна;
    - `ZkFingerprint.exe --selftest`: үр дүнг exe-ийн хажууд `selftest.json` файлд бичээд гарна.

    JSON-ийн утгууд:
    - `serial = "SELFTEST"`
    - `nonce = "selftest-nonce-00000000000"`
    - `imageSha256 = sha256("selftest-image")`
    - талбарууд: `publicKey`, `message`, `signature`

## 7. Дууссаны дараа буцааж өгөх зүйлс
1. Өөрчилсөн файлуудын жагсаалт, товч тайлбар.
2. Шинэчилсэн `CLIENT_GUIDE.md`: шинэ командууд, event-үүд, алдааны кодууд, 3-р хэсгийн криптографийн тодорхойлолт, `ListenAddress` ба `AllowedOrigins` тохиргоо, суулгах үед key хэрхэн үүсдэг.
3. Self-test-ийн гаралт (JSON). Вэб/backend тал түүгээр хоорондын нийцлийг шалгана. Бодит хурууны хээний зураг **бүү** хавсарга.
4. Key машины түвшинд үүсч чадсан эсэх, эс бөгөөс ямар хувилбар сонгосон.
5. Шийдэгдээгүй асуудал, эрсдэл.
